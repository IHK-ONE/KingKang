> 目标：把 dsh-web 的默认客户端能力完整适配到 KingKang for Android。
>

## 1. 目标、范围与完成定义

### 1.1 目标

“完整适配”指：

1. dsh-web 的每个默认客户端模块，在 Android 上都有明确入口和可用交互。
2. 高频操作原生实现；桌面专属、任意插件 UI、长尾管理项通过 Harness 深链兜底。
3. 不要求像素级复刻桌面布局，但信息与操作不能缺失。
4. 原生入口不能出现无响应、假成功、文件拿不到、点了没反应。

说明：任意插件 UI 与完整设置树属于 dsh-web 的运行时页面，无法在不复制 dsh-web 的前提下全部原生化；本计划将其定义为“深链可达”，其余默认模块全部原生。

### 1.2 范围

| 归属 | 内容 |
| --- | --- |
| 原生 | 对话、轨迹、工具卡片、审批、提问、计划/Todo、队列、模型与推理等级、权限预设、Agent 预设、命令/技能、附件、子 Agent、会话管理、工作区、插件开关/安装/卸载、核心设置、工作台、文件与预览 |
| Harness 深链 | 完整设置树、插件自定义页面、插件市场详情、账户登录、工作流复杂编辑、任意第三方插件 UI |
| 不适用 | 桌面快捷键、桌面右栏布局、Open In、桌面系统目录对话框、多窗口 |

### 1.3 完成定义（DoD）

- [ ] 模块对照矩阵中不再有未解释的 `✗`；每个模块要么 `✅` 原生，要么 `▣` 有明确 Harness 深链，要么 `—` 有原因。
- [ ] 所有原生入口都能完成闭环：导出有文件、下载有通知、打开有目标应用、失败有提示。
- [ ] 所有已知 projection / 事件要么被渲染，要么被明确忽略并记录原因。
- [ ] 每个 dsh 设置项从原生设置或 Harness 深链两次点击内可达。
- [ ] 大文件、长会话、大 diff、弱网、权限拒绝都有可恢复的路径。
- [ ] 对照回归、自动化测试、性能与无障碍检查通过。
- [ ] README、协议文档、截图与发布说明同步更新。

### 1.4 适配原则

1. **dsh 是唯一数据源**：设置、会话、插件状态不在应用内复制一份独立配置。
2. **事件驱动**：使用 projection / event 更新 UI，不轮询。
3. **原生优先，Harness 兜底**：高频、触屏友好的能力原生；管理型、桌面型、任意插件 UI 深链。
4. **渐进降级**：未知事件、未知工具视图、缺失字段都要有安全回退。
5. **安全默认**：只连 loopback，不主动 root，密钥只写不读，外链先确认。
6. **可测试**：协议解析与关键交互有 fixtures / 自动化测试，dsh 升级先跑契约测试。

### 1.5 安全与隐私约束

- Kali 与 dsh 只在 loopback 运行，不连接远程 Kali。
- 不尝试 root / `su`；chroot 仅在设备已自行授权 root 时可用。
- API Key 只写入 dsh 凭证存储，应用不回读、不日志、不写入备份。
- 下载文件必须做文件名净化与路径校验，只写入应用私有目录或用户确认的位置。
- 外链只允许 `http` / `https`，打开前确认；禁止 `file://`、`intent://`、`javascript:`。
- WebView JS 桥只对 loopback origin 暴露，校验来源。
- 麦克风/摄像头只在 Harness 前台、loopback 页面、用户授权时使用，用完释放。
- 预览/录音/导出产生的临时文件有清理策略。
- 日志与错误上报不包含 token、Key、完整命令输出中的敏感信息。

#### DSH-101 · 消息级分支

`P0` · 依赖：DSH-001 · 状态：☑ 完成

- 现状：原生只有整会话分叉，`session.fork` 未带 `atSeq`；dsh-web 的分支只允许已完成轮次的最后一条消息。
- 做法：按 dsh 实际 RPC 增加 `message.branch`（或给 `session.fork` 传 `atSeq`）；消息菜单增加“从这里分支”；不满足条件的消息置灰并说明原因；成功后跳转新会话。
- 进展（2026-10-30）：`session.fork` 已支持 `atSeq`（`forkSessionAt`），长按消息打开操作菜单，「从这里分支」只在已完成轮次的最后一条回复上可用；其余情况置灰并在菜单里写明原因；成功后刷新列表并打开新会话。

- 做法：`shouldOverrideUrlLoading` 对非 loopback 链接弹确认框，只允许 `http`/`https`；确认后交给系统浏览器；取消有反馈；`file://`、`intent://`、`javascript:` 与其他 scheme 直接拒绝并提示。
- 验收：外链可确认打开；危险 scheme 被拒绝；不再静默失败。

#### DSH-603 · window.open

`P2` · 依赖：DSH-008 · 状态：☑ 完成（2026-10-30）

- 做法：实现 `onCreateWindow`；用禁用 JS、阻断网络加载的临时 WebView 捕获目标 URL，3 秒未导航即销毁；loopback 目标回到 Harness 主 WebView，非 loopback 走 DSH-602 确认，危险 scheme 拒绝。不会无限弹窗，弹窗 WebView 不保留。
- 验收：`target=_blank` 可用；不会无限弹窗；返回行为正确；资源释放。

#### DSH-604 · 麦克风、摄像头与拍照

`P2` · 依赖：DSH-008 · 状态：☑ 完成（2026-10-30）

- 做法：`onPermissionRequest` 只处理麦克风与摄像头；必须同时满足 Harness 处于前台、请求 origin 与当前 Harness 完全同源（scheme/host/port，loopback）、用户同意 Android 运行时权限，否则立即拒绝。授权后顶部显示「正在使用麦克风或摄像头」，可手动停止；页面导航、退到后台、离开页面都会执行注入的 `__kkStopMedia`，停止所有 `MediaStream` 轨道并清空 `srcObject`。
- 拍照：文件输入带 `capture` 且接受 `image/*` 时，申请相机权限后用 `TakePicture` + FileProvider 写入应用缓存；临时文件保留 24 小时后在下一次拍照时清理；取消或失败返回空结果。Manifest 声明 CAMERA 与可选硬件特性。
- 验收：Harness 内语音插件可录音；拍照可附件；非 loopback/非同源请求被拒绝；权限拒绝不崩溃。

#### DSH-605 · 错误页、离线与重试

`P1` · 依赖：DSH-006 · 状态：☑ 完成（2026-10-30）

- 做法：`onReceivedError`（主 frame）与 `onReceivedHttpError`（主 frame 4xx/5xx）显示原生错误页；Chromium 错误文本按“dsh 未监听 / DNS / 离线 / 证书 / 超时”翻译成可操作说明；重试按钮重新加载现有 WebView；Agent 连接恢复为 Ready 且页面处于错误态时自动重载一次，避免错误页循环。
- 验收：停掉 dsh 后打开 Harness 显示明确提示；重试可恢复；不白屏。
- 未覆盖：错误页没有按“dsh 未就绪/网络/证书”分别提供不同操作按钮，只有重试与说明。

## 5. 不适用与保留 Harness

| 项 | 处理 | 原因 |
| --- | --- | --- |
| `shortcuts` | 不适用 | 桌面键盘快捷键，手机无对应操作 |
| `right` 右侧栏布局 | 改为页面/Sheet | 手机宽度不足，功能由工作台、文件页、终端页覆盖 |
| Open In | 不适用 | 依赖桌面宿主 |
| 桌面系统目录对话框 | 用应用内目录选择器替代 | Android 无法直接选择 Kali rootfs 路径 |
| 任意插件自定义 UI | Harness 深链 | 无法安全、通用地原生渲染第三方 UI |
| 完整设置树 | 核心原生 + 长尾 Harness 深链 | 设置项多且随 dsh 版本变化 |
| 插件市场详情/账户登录 | Harness 或原生简版 + 深链 | 流程涉及第三方页面与凭证 |
| `secret-mask`、`entry-customization`、`deepseek-model-label` 等展示型插件 | 不专门适配 | 纯展示/外观，影响小 |

## 8. 风险与待确认

### 8.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| dsh 0.2.x API/事件变动 | 适配层回归 | 固定基线、契约测试、适配层隔离、升级前跑 fixtures |
| WebView 下载鉴权复杂 | 导出/附件下载失败 | Cookie 透传、blob 降级、原生 bridge 导出兜底 |
| 大 diff / 大工具输出 | OOM、卡顿 | 虚拟化、大小上限、按需加载、降级外部打开 |
| 语音插件协议未知 | 语音无法按预期工作 | 先做验证；原生 SpeechRecognizer 优先；Harness 麦克风兜底 |
| 设置 RPC 覆盖不全 | 部分设置无法原生写入 | 原生核心 + Harness 深链，明确标注 |
| 文件路径与权限 | 预览/打开失败或越界 | 路径规范化、只读优先、FileProvider、用户确认 |
| WebView Cookie 共享 | 本地页面拿到 dsh Cookie | 浏览器独立进程/数据目录，域名与端口风险说明 |
| targetSdk 28 的通知行为 | Android 13 通知不显示 | 真机验证，失败降级为应用内提示 |
| PRoot 性能 | 大文件预览/解压慢 | 后台线程、进度、取消、限制 |

### 8.2 待确认决策

| 决策 | 建议 |
| --- | --- |
| 设置长尾是否全部原生 | 核心设置原生；长尾 Harness 深链，保证两次点击内可达 |
| 语音输入实现方式 | 先原生 `SpeechRecognizer` 转文字；dsh 音频协议确认后再决定是否上传音频 |
| 是否本期做英文 | 放 P2 末期；先保证中文完整 |
| 内置浏览器是否允许非 loopback | 默认只允许 loopback；其他地址必须确认，且使用隔离数据目录 |
| 是否像素级复刻 dsh-web | 不做；以功能等价、触屏可用为准 |
| 插件自定义 UI 是否原生 | 不原生渲染；统一 Harness 深链 |
